# Data Model Specification

**System:** Support Ticket Management v1  
**Store:** PostgreSQL (runtime); H2 allowed in automated tests

Logical names below are specification names. Physical table/column naming is an implementation choice if mapped 1:1.

---

## 1. Relationship

- A **Ticket** has **zero or more Comments**.
- A **Comment** belongs to **exactly one Ticket**.
- Relationship: **one-to-many**, Comment.ticketId → Ticket.id.
- **On ticket delete:** not applicable in v1 (tickets are not deleted). If a database FK is used, `ON DELETE` policy is unused in product flows. **AD-DATA-001:** FK `ON DELETE CASCADE` is acceptable so tests can clean up; product has no delete API.

Comments are not shared across tickets.

---

## 2. Ticket

| Field | Type | Constraints | Notes |
|-------|------|-------------|--------|
| id | UUID | PK, not null, generated by backend | Never supplied by client |
| title | string | not null, not blank after trim, max 200 after trim (**AD-VAL-003**) | Stored value is trimmed |
| description | string | nullable, max 10_000 as supplied | Optional; not trimmed |
| status | enum | not null | `OPEN`, `IN_PROGRESS`, `RESOLVED`, `CLOSED`, `CANCELLED` |
| priority | enum | not null | `LOW`, `MEDIUM`, `HIGH`; default `MEDIUM` on create |
| assignee | string | nullable, max 200 as supplied | Optional; no FK; not trimmed |
| createdAt | timestamp with time zone | not null, set on insert | |
| updatedAt | timestamp with time zone | not null, set on insert and every ticket update including status | |

**Create defaults**

- `status` = `OPEN`
- `priority` = `MEDIUM` if not provided
- `createdAt` = `updatedAt` = server now (UTC)

**Indexes (appropriate for v1)**

| ID | Index | Purpose |
|----|--------|---------|
| AD-DATA-002 | Index on `status` | Status filter |
| AD-DATA-003 | PK on `id` | Lookup by UUID |

Full-text indexes for search are **not** required; `LIKE`/`ILIKE` on title and description is sufficient for v1 (no pagination).

---

## 3. Comment

| Field | Type | Constraints | Notes |
|-------|------|-------------|--------|
| id | UUID | PK, not null, generated by backend | **AD-DATA-004:** comment ids are UUIDs, consistent with tickets |
| ticketId | UUID | not null, FK → Ticket.id | |
| body | string | not null, not blank after trim, max 5_000 after trim | Stored value is trimmed |
| author | string | nullable, max 200 as supplied | String only; may be omitted; not trimmed |
| createdAt | timestamp with time zone | not null, set on insert | Comments are not updated in v1 |

**Indexes**

| ID | Index | Purpose |
|----|--------|---------|
| AD-DATA-005 | Index on `ticketId` | Load comments for a ticket |
| AD-DATA-006 | PK on `id` | Identity |

**Ordering:** comments for a ticket are returned in `createdAt` ascending, then `id` ascending for ties (**AD-DATA-007**).

---

## 4. Enumerations

**TicketStatus**

`OPEN` | `IN_PROGRESS` | `RESOLVED` | `CLOSED` | `CANCELLED`

**TicketPriority**

`LOW` | `MEDIUM` | `HIGH`

Store as string enum or PostgreSQL enum; mapping is an implementation choice. Values must match the API exactly (uppercase with underscore).

---

## 5. Integrity rules

| Rule | Enforcement |
|------|-------------|
| Comment cannot exist without a ticket | FK + service checks ticket exists before insert |
| Status values only from TicketStatus | DB check/enum + API validation |
| Priority values only from TicketPriority | DB check/enum + API validation |
| Transition legality | **Service/domain only** (not a DB state-machine graph) |

---

## 6. What is not modeled

- Users, roles, sessions
- Ticket history / audit log table (not required; `updatedAt` is sufficient)
- Soft-delete flags
- Attachments
